## 1. Code implemented in this first iteration

1. **Tokenizer-bounded structural chunking:** `TextChunkingService._preferred_boundary` now prefers the start of a complete Markdown `#` through `######` heading when it falls in the latter half of a fitting chunk. This keeps a heading with its following section when possible. It still falls back to paragraph/newline/sentence/word boundaries, uses exact tokenizer count and rejects oversized input without dropping/reordering normalized characters. It does **not** promise topic-boundary detection in PDF/DOCX plain text.
2. **Validated decoder repetition control:** `Mt5ModelProvider` supports integer `model.no_repeat_ngram_size` in **[0, 6]**; zero is compatible with the Stage 9 decoding behavior. The option is passed to the pinned Hugging Face `generate` call; model lifecycle, resource ceilings, concurrency and DI are unchanged.
3. **Configuration separated by environment:** `appsettings.development.yaml` enables trial `no_repeat_ngram_size: 3`. The production `appsettings.yaml` explicitly keeps `0` so **production decoding** remains the Stage 9 default. The section-boundary heuristic is shared by both environments; it is lossless but can change chunk grouping. The development config can be rolled back by changing `3` to `0` (without touching weights or deleting files).
4. **Auditable experiment:** `quality_benchmark run` now records `no_repeat_ngram_size` in the generation metadata. A new `benchmarks.stage10_compare` CLI compares fixed input cases/tier pairs, output lengths, n-gram repetition, elapsed times, token counts and generation configurations. It refuses mismatched dataset digests or case/length sets. It never copies raw summary text or unknown metadata into its comparison report and **never claims semantic improvement without human reviews**.

This is one **joint candidate** (chunk boundaries + decoder n-gram setting), not a causal experiment isolating every knob. Further ablation of `num_beams`, `length_penalty` and `repetition_penalty`, map/reduce preservation and human annotation are future iterations **within Stage 10**. Changing all three decoder parameters at once would confound comparisons.

## 4. Diagnostics, risk and rollback

- **Model errors vs extraction:** Synthetic TXT-as-direct-input and Markdown pass through the model pipeline without PDF/DOCX extraction; failures here cannot be assigned to an extractor. The 8-page source PDF remains unavailable.
- **Map/reduce loss is an unverified hypothesis:** Observed long-document fact omissions do not isolate whether facts vanish during chunking, map generation or the final reduce. Intermediate text must be checked under a safe, explicitly consented local diagnostic (do not log sensitive chunks in production).
- **Decoder n-gram blocks can reduce repetition but may force premature EOS** or prevent legitimate repetitions. They do **not** check whether numeric/directional claims are supported.
- **Shared chunk-boundary change:** the heading preference applies to text containing Markdown headings even in production; previous arbitrary text and API shape remain unchanged, but production output for headed documents may change. The exact full regression suite and CPU benchmark must be checked before rollout.
- **Rollback decoding trial:** set `model.no_repeat_ngram_size: 0` in `src/host/res/appsettings.development.yaml` and restart the process; `appsettings.yaml` already uses zero. To roll back section-aware chunk grouping, revert that commit rather than removing tokenizer safety checks.
- **Not yet verified:** actual candidate CPU outputs, semantics, reliable mean/warm latency, peak RSS, PDF/DOCX E2E, holdouts, full Windows suite after this change. All remain **Not Run / Unreviewed** until evidence is provided.

**Stage 10 status: In Progress**, not Completed. Next decision: evaluate candidate on the two fixed dev benchmarks, review atomic factual labels, and iterate on map/reduce only when comparisons demonstrate specific residual failures.
