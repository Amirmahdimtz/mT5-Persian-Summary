## 4. Stage 10 quantitative gates — provisional, pre-tuning

The following pre-specified **seed development gates** prevent cherry-picking and define what a minimally useful improvement would look like. These are **not yet final sign-off criteria** for production-quality Persian summarization; they need a reviewer and representative-file benchmark approval.

| Dimension | Seed baseline | Proposed initial Stage 10 gate | Failure condition |
| --- | --- | --- | --- |
| Fact Coverage (`medium`, 19 expected facts) | 3/19 (15.79%) | **≥8/19 (42.11%)** while preserving factual correctness | Smaller gain or improvement driven by fabricated facts |
| Critical direction flips | 2 clear inversions | **0** for pollution reduction and software support expense increase | Either inversion remains |
| Fact Distortion | 2/19 (10.53%) | **0/19** on these critical small-fixture examples | Any new incorrect date/number/person or changed direction |
| Unsupported Claim Rate | 3/8 (37.5%), one judgment-sensitive | **≤12.5%** under agreed claim segmentation; alternative stricter criterion: no demonstrably invented critical claim | Increase or unverifiable assertion masked by a different claim split |
| Short / Medium / Long behavior | identical on 5/5 cases | **At least 3 of 5** cases have distinct `short` vs `long`, with `long` not shorter than `short` | Identical at all tiers, or length gained by repetition/hallucination |
| Runtime compatibility | 289 passed, 2 nonblocking warnings (user) | No regression in full suite and the 23 original Stage 9 tests | Broken API, DI, chunk limits or document extraction |
| Real-document evaluation | not run | Report dev corpus with explicit verified annotations and honest latency/memory measurements; reserve holdout | Claimed success without actual model outputs and review |

**Evaluation protocol:** Treat seed cases as diagnostic regression fixtures, not a representative test set. Score each source once per length tier without counting identical tiers as independent. All claims must cite original text and be human-reviewed. Evaluate actual long and multi-topic documents separately, noting extraction vs inference failures. When Stage 10 candidates are selected, run the two holdout categories only for final evaluation, not for parameter tuning. Benchmark thresholds can be revised **before** tuning if documented with rationale and reviewer sign-off; do not alter them after seeing a candidate result without marking it a new protocol version.
